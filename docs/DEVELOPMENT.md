## Запуск из исходников

Для воспроизводимой установки используйте **Node.js 24** и **pnpm 11.25.0**. Откройте терминал в папке исходников `wallbloom/` и выполните:

```sh
pnpm install --frozen-lockfile
pnpm start
```

`pnpm start` открывает приложение Electron. Для браузерного режима выполните `pnpm run start:web` и откройте <http://127.0.0.1:43198>.

Lockfile и локальные патчи зависимостей включены в проект. Используйте pnpm, чтобы применялись зафиксированные версии и исправления.

## Проверки и сборка

```sh
pnpm run check
pnpm test
pnpm run build:win
```

Готовая сборка: **`dist/WallWave-Windows-x64.exe`**. Распакованная: `dist/win-unpacked/WallWave.exe`; сохраните остальные файлы этой папки рядом.

Корневая папка рабочего пространства содержит готовый `WallWave.exe`, установленное приложение в `WallWave/` и архив в `archive/`. Репозиторий Git находится только в `wallbloom/`.

Перед коммитом включите [проверки личных данных](PRIVACY.md): `git config --local core.hooksPath .githooks`.

Тесты работают во временной библиотеке и не меняют обои рабочего стола. Дополнительные браузерные сценарии: `tools/check-ui.mjs`, `tools/check-redesign.mjs`; передайте путь к папке Node-пакетов с Playwright. Для них нужен установленный Edge.

`node check-source.mjs` проверяет поиск и теги Wallhaven без скачивания изображений и без API-ключа. GitHub Actions запускает тесты на Windows при отправке коммитов и создании pull request.

## Данные приложения

Библиотека находится в **`%USERPROFILE%/Wallbloom/library`**. Название этой папки сохранено для совместимости с существующими данными.

`WALLBLOOM_DATA_DIR` задаёт другую папку данных; `WALLBLOOM_IMPORT_DATA_DIR` — источник для однократного переноса библиотеки. Старая библиотека копируется при первом запуске, только если новой ещё нет; исходные данные сохраняются.

Настройки, оценки и ключи имеют резервные файлы `.backup`. При повреждении или отсутствии основного файла приложение читает резервную копию. Удаление ключа очищает и его резервную копию.

Desktop-сервис выбирает свободный локальный порт автоматически. Его нельзя считать постоянным.

## Лицензии

Исходный код распространяется по **MIT**. Права на сторонние изображения и веса моделей определяются их собственными лицензиями. Изображения, пользовательская библиотека, ключи, зависимости и сборки исключены из репозитория.

## Подбор и локальная модель

По умолчанию работает лёгкий алгоритм: теги интересов, оценки, средний цвет уже скачанных изображений. Цвет применяется для ранжирования библиотеки после загрузки; теги помогают выбирать ещё не скачанное. Поиск не обещает нейросетевого сходства в этом режиме.

Опциональная CLIP: выберите экономный или обычный режим. В готовом приложении зависимости уже включены; веса [Xenova/clip-vit-base-patch32](https://huggingface.co/Xenova/clip-vit-base-patch32) скачиваются только при первом анализе, если их ещё нет в кэше. Используется [Transformers.js](https://huggingface.co/docs/transformers.js/). Это визуальные векторы и сравнение с твоими оценками, без обучения новой нейросети и без генерации изображений.

Модель работает в отдельном процессе на CPU, 1 или до 2 потоков, с пониженным приоритетом. Не больше 8 изображений и 3 минут за запуск. Проверка свободной памяти и активности останавливает процесс; уже полученные векторы сохраняются. Пороги: 8 ГиБ общей RAM и 3 ГиБ свободно перед запуском; остановка при менее 2 ГиБ свободно. Это защитные пороги, не подтверждённые минимальные требования. GPU не используется. При первом запуске модель может не успеть скачаться за 3 минуты; повторный запуск использует кэш. Ошибка проверки активности запрещает фоновые задачи.

## Источники и 18+

На Wallhaven 18+ требует регистрации и собственного API-ключа: [документация API](https://wallhaven.cc/help/api), [настройки аккаунта](https://wallhaven.cc/settings/account). Ключ вводится в карточке источника. Интерфейс не получает сохранённый ключ обратно. Файл `data/credentials.json` хранит ключ **без шифрования**; папка `data` исключена из Git. Не публикуйте её и не передавайте другим людям.

Для локальной папки явно выбирается её категория: содержимое классифицируешь ты. В пользовательском каталоге каждое изображение должно иметь категорию. При safe картинки из adult-источника не импортируются. Это доверие метаданным источника; нейросетевой модерации нет.

Свои каталоги подключаются без редактирования программы:

```json
{
  "items": [
    {
      "id": "landscape-01",
      "title": "Mountain lake",
      "url": "https://example.org/images/lake.jpg",
      "source": "https://example.org/photos/lake",
      "tags": ["nature", "mountains"],
      "rating": "safe",
      "popularity": 120
    }
  ]
}
```

Максимум 500 записей и 2 МиБ JSON. `rating`: `safe`, `suggestive`, `adult`. URL изображения — публичный HTTPS. Переадресации проверяются; приватные адреса и локальная сеть запрещены. Пользовательские API с авторизацией пока не подключаются напрямую: для них нужен отдельный адаптер. Возможность добавить любую библиотеку означает подключение папки или каталога по этому формату, а не совместимость с любым существующим API.

Ссылки на источник сохраняются. Право скачивания и использования зависит от лицензии каждой картинки; приложение не делает содержимое сторонних источников собственностью проекта. В репозиторий изображения не включаются.

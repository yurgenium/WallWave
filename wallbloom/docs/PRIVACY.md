# Защита личных данных при публикации

[Вернуться к описанию](../README.md)

## Что остаётся на компьютере

CLIP анализирует изображения и их миниатюры на компьютере. Изображения и оценки не отправляются внешнему ИИ. При первом включении модели скачиваются с Hugging Face. Проверка новых обоев запрашивает миниатюры у источника; отклонённые оригиналы не скачиваются. Признаки изображений и решения фильтра хранятся в пользовательской библиотеке.

Обои, оценки, предпочтения, настройки источников и API-ключи находятся в `%USERPROFILE%\WallWave\library`, вне папки исходников. Установленное приложение в соседней папке `WallWave/` и старые файлы в `archive/` также не входят в этот репозиторий.

Диагностика сохраняет локально ограниченную хронологию технических действий и ошибок. Отчёт включает среду выполнения, источник действия, результаты операций и топологию всех экранов. Интересы, теги, оценки, конкретные категории, названия и идентификаторы обоев, адреса, ключи, пути и сырые сообщения исключений не записываются. Используются разрешённые поля; очистка повторяется при экспорте старой истории. Подробнее — [формат и правила диагностики](DIAGNOSTICS.md). Отчёт отправляется только когда пользователь сам прикладывает его к сообщению.

`.gitignore` исключает библиотеки, экспорты, личные JSON-файлы и резервные копии, сведения об установке, журналы, изображения, модели и готовые сборки. Среди изображений разрешены только пять известных значков приложения.

## Проверка перед сохранением и отправкой

```sh
node tools/check-repository.mjs
node tools/check-repository.mjs --history
```

Первая команда проверяет пути файлов в индексе Git; вторая — пути во всей доступной истории. Проверка блокирует личные файлы, даже если они добавлены с `git add --force`.

В текущей рабочей копии включены Git hooks: проверка запускается перед коммитом и отправкой. Для другой рабочей копии включите их командой:

```sh
git config --local core.hooksPath .githooks
```

GitHub Actions повторяет проверку файлов репозитория. Исключения и hooks защищают от случайного добавления файлов, но их можно намеренно обойти. Они не распознают личную информацию, вручную вставленную в исходный код или документы. Не добавляйте такие сведения в публикуемые файлы.

## Проверка выпуска 0.5.13 — 15 октября 2026 года

В проверенной истории Git не обнаружены файлы пользовательской библиотеки, настройки, предпочтения, API-ключи или скачанные обои. Из графических файлов в истории есть только значки приложения. Проверка известных форматов секретных токенов в исходниках также не выявила совпадений.

Локальные резервные копии, архивы обслуживания и файлы пользовательской библиотеки остаются вне репозитория. Экспорт библиотеки, скриншоты с личными обоями и готовые сборки проверяются отдельно перед публикацией, например через GitHub Releases. Состав EXE проверяет `tools/check-package.mjs`: пользовательские данные и ключи в приложение не включаются.
